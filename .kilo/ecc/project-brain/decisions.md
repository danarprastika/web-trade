| EXD-011 | WI-117's AC4 durable-buffering gap is closed by the transactional outbox (WI-120 + WI-121), not by a write-ahead log and not inside WI-117 alone. `Guard.pending` becomes `count(*) FROM audit_outbox WHERE dispatched_at IS NULL`, and the audit record plus its signed checkpoint are committed in the same transaction as the business mutation | `docs/22` §4 requires the audit stream to be written "transactionally with the business mutation or outbox event", and `docs/08` §13 refuses to trade a safety invariant against availability. A WAL is worse: `AppendAuditRecord` deliberately has no `ON CONFLICT`, so replaying an already-exported `audit_id` is a hard conflict rather than a no-op, and the chain-link trigger refuses a partially replayed log. Building an outbox inside WI-117 would duplicate the mechanism the outbox exists to prevent | Accepted — blocks the write path, not WI-117 | `.kilo/plans/1790888029810-audit-backlog-durability-design.md`, `docs/22` §4, `docs/08` §13, ADR-006 |
| EXD-012 | The control-plane write path stays unwired (`write_path_exposed: false`) until EXD-011's outbox exists. `Allow`, `ObserveVerification` and `Clear` remain a tested library with no production caller in the meantime | AC4's backlog gap is currently latent rather than bleeding: no record has ever been accepted-but-unexported in a running process, because nothing calls `Accept` outside tests. Wiring the write path first would make the first crash the first loss. The crash path is already detected — `verifyAgainstChain` refuses to boot with "registry has drifted from the evidence" — so today registry/audit corroboration is a load-bearing backstop, and it must be preserved or replaced by the new design rather than assumed | Accepted — sequencing constraint | `main.go:435`, `journal.go:368`/`:377`, `verifyAgainstChain`, WI-117 |

| EXD-013 | Commit `7342229`'s message describes an operator clearing a system that held a detected chain break. That scenario was **not reachable** when it was written: `ObserveVerification`, `Halt`, `Clear`, `Accept` and `Allow` had no production caller, so the chain-break half of the escalation could not fire in a running process. The message is immutable and stands uncorrected in history; the corrected statement of reachability lives in this register, in `guard.go`'s own comments, and in `harness_test.go` / `destructive_guard_test.go`, whose prose was revised to stop implying a live write path | The fix is real and stays — `Halt` does now escalate a backlog cause to an integrity cause — but the commit message narrates a production incident that could not have occurred, and a reader taking the message at face value would over-estimate both the urgency of the change and the exposure at the time. Recording the discrepancy here is the only available correction, because a commit message cannot be edited without rewriting history and the finding itself was accepted on the strength of the message. EXD-012 already establishes that `ObserveVerification` and `Clear` have no production caller, so this entry narrows an existing fact to the one place it was overstated rather than introducing a new claim | Accepted — corrective record, no code change | `7342229`, `guard.go`, EXD-012, EV-070, EV-072 |
| EXD-014 | A recorded finding is re-read against the code before it is implemented. Two of the four findings carried from the previous review did not survive: F5's proposed change would have inverted three deliberate tests (`audit/restore_test.go:283` and `:297`, and `model/journal_test.go:118`) and made `Chain.Append` unusable, and F7 was already complete and documented as intentional. An independent review re-derived both conclusions independently and agreed | `Chain` owns hash linkage and `Anchor` owns attestation; a chain legitimately extends past its last checkpoint, so requiring total coverage in `Verify` contradicts the design rather than enforcing it. F7's remaining literals are in tests on purpose, because a test that used the constant would pass vacuously on a typo. The generalisable point is that a one-line summary of a diff can omit the design rationale that the surrounding tests encode, and acting on the summary would have produced a regression dressed as a fix | Accepted | EV-072, WI-172, `audit/restore_test.go`, `model/journal_test.go`, `audit/guard.go:22-23` |
