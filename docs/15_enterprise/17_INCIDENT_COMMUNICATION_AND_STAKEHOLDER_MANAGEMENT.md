# Incident Communication and Stakeholder Management

> Status: ENTERPRISE DOCUMENTATION BASELINE v1.2.0 — controlled planning baseline; subordinate to the applicable Normative Core and approved contracts.

## Purpose
Make incident communication controlled, factual and auditable.

## Authority and interpretation
- This document defines control intent and operating expectations; it does not silently approve unresolved values, credentials, legal positions, capital limits, or live activation.
- Where a value is marked TBD, it requires explicit owner-approved decision evidence before implementation may depend on it.
- Same-tier conflicts are fail-closed and require a recorded change request or decision.

## Communication classes
Operational degradation, trading halt, security incident, data integrity issue, provider incident, recovery and post-incident review.

## Message requirements
What happened, affected scope, current safety state, actions taken, next review point and owner. Avoid unsupported speculation.

## Channels
Web control center, Telegram notification path and internal incident records must follow the same authoritative incident state.

## External communications
Any regulated, contractual or public communication follows the applicable organizational approval process; this document does not define legal reporting obligations.
